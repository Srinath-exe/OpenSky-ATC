Choosing the aircraft by likelihood, not one token at a time

The 2M-parameter voice model turns the game state and a transcript into a command line. It used to pick the callsign greedily, token by token, through a trie of the callsigns in the state. Now every callsign is scored by its full likelihood and the best one wins, found by an exact best-first search that costs one or two extra model steps.

13.7%→6.0%

Commands wrong at Sydney, an airport the model never saw (2m-grpo-v1, the model the game ships; n = 1000). Callsign accuracy there went from 91.4% to 99.6%. Same weights, no retraining: only the decoder changed.

The failure

Greedy decoding commits to the airline before it reads the digits

A real Sydney row, decoded by 2m-swap-v1. The controller only said the flight number. The decoder's first token must be one of the callsigns' first tokens, and greedy picks the most likely one. At Sydney that is Qantas: most traffic is QFA, so the model's prior for QFA is high before any digit has been considered. Once QFA is chosen, the best the digits can do is QFA71, and the trie then stops constraining (a complete callsign), so the model carried on to QFA717, an aircraft that is not in the state.

Each segment is one token's − log probability (hover for the number); the last one, “␣”, is the word boundary: the probability that the callsign ends there. QFA is cheap (1.2 nats) but its digits cost 15 and 13 nats; VOZ is expensive (5.9 nats) and then every digit is free. Summed over the whole callsign, the gold one wins by 32 nats.

The decoder

Score the whole callsign, and search for the best one exactly

Score. score(callsign) = Σ log p(token) over " VOZ527" + log p(word boundary after it). The boundary is any token that starts with a space, or <eos>. Without it UAL12 would always beat UAL123, because a shorter prefix has fewer tokens to pay for. The shipped score is length-normalised: divided by (tokens + 1). It ties the plain sum on validation and Sydney, and wins on real recognisers, where the sum over-prefers the 2-token SAY AGAIN (table below).

Search. Scoring all ~14 candidates of a state means ~47 model steps (shared prefixes counted once) against ~4 for the greedy path. But log-probabilities are ≤ 0, so a prefix's score is an upper bound on every callsign below it. A max-queue over the trie can therefore stop at the first complete callsign it pops: nothing left can beat it. That is best-first search, A* when length-normalised (bound: prefix log-prob ÷ (longest callsign below it + 1)). It returns exactly the full-scoring argmax: same pick on all 6,000 eval rows.

14 model steps. The first 10 find the answer (the airlines the prior likes are tried first; one step each shows that the next digit does not fit). The dashed ones look for the runner-up, for the verifier's margin signal; that phase gets at most 4 steps, then the margin is reported as best minus the highest bound left (1.15 here) — a lower bound, never an over-estimate.

In the browser the KV cache is branched per trie node: each stepped node's keys and values (4 layers × 2 × 192 floats) are saved, and before a node is stepped its ancestors' are copied back into positions P, P+1, … of the one preallocated cache. The arithmetic is the same step() as before, so the result is identical to a straight decode of that callsign.

Verifier

The gate was refitted on the new decoder's signals

The decoder's per-token signals feed the verifier that decides send / check / say again. They are now taken along the chosen callsign's path (the trie margin can be negative when the likelihood overrules the greedy choice), and two are new: the chosen callsign's log-likelihood and its margin over the runner-up. The gate was refitted per model with ml/verify/refit.sh.

A bug surfaced on the way. ml/verify/fit.py reused the names mu, sd for the S1-trunk experiment, so the exported gate carried the 384 hidden-state means and deviations instead of its 28–30 feature statistics. The game standardised every feature with the wrong numbers: the gate that ran sent far more wrong commands than the report said. Fixed, and fit.py now asserts that the exported gate reproduces the fitted one. To separate the two effects, the greedy-trie decoder also got a correctly exported gate (middle row).

For an AI engineer

What this teaches

  • Greedy is a search with a horizon of one token. Constrained decoding (grammars, JSON schemas, here a callsign trie) masks invalid tokens but still commits token by token. When the evidence comes late in the sequence, score whole sequences.
  • A prior on the first token is how this fails. The model knew VOZ527 fit the digits; the decoder never asked. Accuracy went up 7 points at Sydney without touching the weights.
  • Compare sequences fairly. Sum of log-probs favours short candidates. A boundary term makes prefixes compete (UAL12 vs UAL123); length normalisation removes the bias towards the 2-token SAY AGAIN.
  • Bounds make exact search cheap. Log-probs only fall as a sequence grows, so best-first / A* returns the exact argmax after a handful of steps when the model is confident. Beam search would cost twice as much and is only approximate.
  • Change the decoder, refit what reads it. The verifier was fitted on the old decoder's signals; new decoder, new distributions, new gate.
  • The idea came from the diffusion experiment (voice-diffusion), where scoring every callsign by likelihood lifted the diffusion model's Sydney callsign accuracy from 91.9% to 99.1%. It carries over to the autoregressive model unchanged.
