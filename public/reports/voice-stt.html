Speech-to-text for ATC: why push-to-talk misheard you, and the fix

The owner tried voice in the game: "the STT is so bad". Measured on 640 realistic clips, the recognisers were not the only problem; generic speech-to-text writes ATC speech in ways the rules cannot read ("Happy Bird 50", "Speedbird 2, 73, Climb 1, 3000"), it is never told which callsigns are on frequency, and the first word (the callsign) is lost when the microphone starts late. The fix: every transcript is now repaired against the aircraft on frequency, every guess the recogniser had is tried (n-best), the microphone keeps a pre-roll, and when the browser's guesses are still not understood, this game's own server listens again with Whisper told the callsigns on frequency.

Words used here
WER (word error rate)(substituted + inserted + deleted words) ÷ words said. Numbers are put in one form first, so "four two one" and "421" match.
Exact commandthe command line the game ends with parses to the same command as the one that was spoken (same aircraft, same instruction, same numbers).
Contextual biasing (hotwords)telling the recogniser which rare words to expect. For Whisper: a text prompt it treats as "what was said before" (here: the callsigns on frequency).
n-best listthe recogniser's n most likely transcripts, best first. The rules try each; the first that parses wins.
Beam searchdecoding that keeps the k most likely partial transcripts at each step instead of only the best one; it is what produces an n-best list. Here the 2-best is cheaper: one decode with the prompt, one without, sharing the encoder.
Pre-rollaudio kept from just before the key press, so speech that starts a moment early (or a recogniser that starts late) does not lose the first word.
Benchmark

100 validation sessions at 11 airports + 60 from Sydney (never trained on): game state, what the controller said, the command meant. At most 9 per command kind.

make_bench.py

Conditions

clean TTS · laptop room reverb, fan noise 15–25 dB SNR, level −14..−2 dB · radio 300–3400 Hz, compression, 6–12 dB SNR · late laptop with the first 150–400 ms of speech cut

score.ts

Game code scores it

Each transcript goes through the game's own rules, repair, n-best and S1 model in Node; the result is compared with the gold command.

Speech-to-text engines ran on this VPS's CPU (2 threads, shared with five other jobs: load average 18–27, so latencies are pessimistic) or, for Web Speech, in Google Chrome 157 under Xvfb with each clip played into SpeechRecognition.start(MediaStreamTrack). The slow Whisper engines ran on every other situation (80 situations, 320 clips); all comparisons below use that common set.

recognizer.ts · asr-capture.ts

Push-to-talk

Web Speech listens through a 0.3 s delay line on our own microphone stream (start(MediaStreamTrack)), kept open a minute: a pre-roll. 5 alternatives. Recording runs 250 ms past release.

asr-repair.ts · asr-nbest.ts

Repair + n-best

Numbers into one spoken form, homophones, command words by sound, the callsign matched by phonetic key to the aircraft on frequency. Each guess on the rules, best first; then S1 on the raw and repaired text.

/api/voice/stt

Second opinion

Still not understood: the same audio (recorded alongside, with pre-roll) goes to Whisper base.en in this Next.js server, prompted with the callsigns on frequency, decoded with and without the prompt.

understand.ts

Rules, then S1

Both guess lists together. The verifier decides send / check / say again; a callsign matched only by sound with a digit changed is never sent unchecked.

Settings → Voice recognition: "Browser (Google)" (default; Firefox has no Web Speech and gets "Server"), "Server (Whisper, tuned for ATC)" (audio to this game's server only, not to Google, not stored; slower), "On-device (Moonshine)" (moved from tiny to base: 53% → 65%). Biasing Web Speech itself with SpeechRecognition.phrases was tried: Chrome's cloud recogniser rejects it ("phrases-not-supported"); the game sends phrases once and stops on that error. Guards on the public route: 1 MB / 15 s per request, 30 a minute per IP (bursts of 10), one transcription at a time with 4 waiting, 12 s timeout.

Real voices

All of this is synthetic speech. Real voices on a laptop microphone are harder, and Web Speech may do relatively better on them (Google trains on far more real speech than Whisper base). Once the owner has recorded the gold set (/voice/record.html, another agent's recorder), one command scores every engine on it, including the Web Speech transcripts the recorder captured live:

bash ml/stt/bench2/run.sh gold

Writes ml/stt/bench2/results/gold/summary.json and prints the same table as above (Web Speech from the recordings, alone and with the server as second opinion, plus the server and on-device engines). If the server alone beats the browser on real voices, set DEFAULT_VOICE_ENGINE in src/lib/voice/recognizer.ts to 'server'.
