Architecture

One game, one understanding path; the phone adds ears

The Flutter app is a thin native shell. The game stays the website inside a WebView, so the rules parser and the S1 model are the same code the browser runs. The app only does what a page cannot do well on a phone: own the microphone, run a speech model natively, and deliver that model.

Orange = the path your voice takes. Audio exists only in the left half: the page receives text, never samples. The bridge is registered only when a model is installed, so without one the page behaves exactly like a browser.

Picking the model

Hotwords turn a 73 MB LibriSpeech model into a controller's ear

Same 200 clips as the GPU bake-off (neural voices reading real game commands, each with the game state it was spoken in), now run through mobile/tool/stt_bench.dart: the app's own Dart engine, sherpa-onnx 2.0.1, audio fed in 100 ms chunks like the microphone, hotwords built from each clip's aircraft list exactly as the page sends them. Then ml/stt/score.py's definitions: rules alone (L0), and rules with the S1 model as the fallback (L0 + L1, the production chain).

What hotwords fix

  • speedber two seven three → speedbird two seven three
  • fredex nine four seven → fedex nine four seven
  • laska six forty two → alaska six forty two
  • speedbert speedburn → speedbird speedbird
  • reduced speed → reduce speed, ninor → niner

Flight numbers heard: 74% → 91%. Word error rate: 32% → 19.5%. Commands understood end to end: 53.5% → 69%.

Why the zipformer over Moonshine

  • Tied on commands (69.0 vs 69.5%), but 5× faster after release (62 vs 342 ms p50, 138 vs 886 ms p95).
  • Streams: words appear while you are still talking.
  • Can be biased with the aircraft actually on frequency; Moonshine cannot, and that matters more on real, accented voices than on these clean ones.
  • Published as single files on Hugging Face (pinned per file); Moonshine's small build only ships as a tar.bz2.
  • Moonshine stays the runner-up: smaller, trained on far more speech, better at bare flight numbers (97%). It is the first on-phone A/B to run.

Timings are from this VPS (x86, 2 threads) while three training jobs ran (load average 15–26 on 8 cores), so they are pessimistic; a 2022+ phone core is in the same class. The clips are synthetic neural voices: real microphone speech will score lower for every model, which is what the test plan below measures. "Flight no. heard" = the gold callsign's digits appear in the transcript. Whisper turbo is the GPU bake-off's best, for scale only. L1 here is the CPU-trained S1 v1 (the scorer's default) for every row, so absolute numbers sit below the bake-off page's (Whisper turbo: 81% here, 87.5% there); the ranking is what this table is for.

Choices

Where should the speech model run on a phone?

An on-device runtime is the library that executes a trained network on the phone's own CPU/GPU/NPU (no server round-trip, works offline, audio stays local). Four ways to get speech-to-text into the app were on the table:

Transducer. A speech model with an encoder (audio → features), a small prediction network (text so far) and a joiner that picks the next token; it emits text chunk by chunk, so you see words while you speak.
Hotwords (contextual biasing). Phrases given at run time get a score bonus inside the beam search, so "SPEEDBIRD TWO SEVEN THREE" beats "SPEED BIRD TO SEVEN THREE" when that aircraft is on the scope. No retraining.
Quantisation. Storing weights as 8-bit integers instead of 32-bit floats: about 4× smaller and faster on phone CPUs for a small accuracy cost. All the models here are int8.
Model delivery. Getting the weights onto the phone after install: a manifest pinned in the app names each file, its URL (a fixed commit) and its SHA-256, so updates are a manifest change and corrupted bytes are never loaded.
Real-time factor (RTF). Compute time ÷ audio time. 0.1 means one second of speech costs 0.1 s of CPU.
Isolate. Dart's thread with its own memory. Decoding runs in one, so the WebView never stutters while the phone transcribes.
Model delivery

73 MB, fetched once, verified file by file

The weights are not in the APK (it would triple its size and every model update would need a new install) and not in this git repository. The APK carries a manifest; the first run downloads what it names.

What the downloader guarantees

  • URLs name a commit, so the bytes behind them cannot change under the pinned hash.
  • Each file streams to .part; a dropped connection or a killed app resumes with an HTTP Range request (the bytes on disk are re-hashed first).
  • A file is renamed into place only if its SHA-256 matches; a mismatch deletes it.
  • .installed.json is written last; a directory without it is never loaded.
  • Models live in models/<id>/<version>/; installing a new version deletes the old one. Updating a model = a new manifest entry in the next app build.
  • For hotwords sherpa-onnx wants bpe.vocab; the app derives it from the official bpe.model (a small protobuf parser, byte-identical to the Python sentencepiece export).

Test plan

Five steps on an Android phone, and the numbers to read off

Nothing here ran on a phone yet: this VPS has no KVM (no emulator) and no device. Everything up to the APK is built and unit-tested; the steps below close the loop. The live site must carry the web half (createNativeRecognizer) for step 5, so deploy first.

  1. Install. On the phone open openatc.aeon-labs.site/downloads/openatc-1.0.0.apk and allow "install unknown apps" for the browser (or adb install -r openatc-1.0.0.apk). Android 7.0+, arm64.
    read: APK 44.2 MB; installed size in Settings › Apps › OpenATC › Storage
  2. First-run download. The model screen shows the model, its licence and 72.9 MB. Tap Download; switch to airplane mode half-way, then back, then tap Resume: it must continue from the same percentage, not from zero. It finishes by verifying SHA-256 and opens the game.
    read: MB/s and time on your connection; "Speech model ready in N s" (model load) in the top-right chip
  3. Grant the microphone. The first push-to-talk asks for the microphone. Deny once: the game must say "Microphone permission is off…" instead of hanging. Then allow it in Android Settings › Apps › OpenATC › Permissions.
  4. Start an airport. The game opens in landscape at a 1280 px layout, without the "Desktop required" notice. Pick JFK, start a shift, wait for a few aircraft on frequency. Settings › Voice recognition should show Phone selected.
  5. Hold PTT and talk. Hold the PTT button, say "delta four two one, turn left heading two seven zero" (a callsign that is on the scope), release. Partial text appears while you speak; on release the command lands in the bar and is sent if understood. Try ten commands, including a tricky telephony ("speedbird", "jetblue") and a bare flight number.
    read: the chip "on-device STT N ms · RTF x" after each release (target: under 300 ms and RTF under 0.5); tap it for the median over the last 20; how many of 10 were sent without editing

Logs: adb logcat | grep -i -E "flutter|sherpa". If the game page has not been redeployed yet, the app still works as a browser and the chip shows the model status, but PTT uses the page's own recogniser.
