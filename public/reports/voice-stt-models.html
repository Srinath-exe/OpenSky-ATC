On-device: the browser keeps Moonshine base; the phone should switch to it

Nothing new beats Moonshine base in the browser on both sets. Whistle is the light option (18 MB, a quarter of the RAM, about as fast) but 3 to 8 points less accurate. On the phone, the app's streaming zipformer is the weakest engine measured; the same sherpa-onnx runtime runs Moonshine base, which is 10 to 19 points better.

Best

  • Browser: Moonshine base stays the default. Best accuracy of anything that runs in a normal (not cross-origin-isolated) page on one WASM thread: 67.2% / 75.0%. Whisper tiny.en scores higher but takes about 4 s per transmission in WASM.
  • Phone: Moonshine base through sherpa-onnx (67.8% / 76.9%, sent wrong 5.9% / 1.9%), a model swap inside the runtime the app already has (its engine already supports the 'moonshine' kind). Parakeet 110M with hotwords is close (better on US/UK, worse on the Indian proxy, CC-BY); Phonon-2.5 is the most accurate but a 0.94 GB download.

Shipped

  • public/voice/stt-worker.js: a Whistle engine (?model=whistle): the Cactus engine's WASM build and the .cact weights from pinned Hugging Face revisions, cached with the Cache API, keyword-biased with the airline names on frequency and the ATC command words; transformers.js is now imported only for the engines that use it; a failed model load is retried on the next push-to-talk.
  • src/lib/voice/recognizer.ts: the game page's ?stt-model=whistle (or tiny, whisper-tiny.en) picks the on-device model; the default is unchanged (Moonshine base), so the settings label is unchanged.
  • mobile/STT_MODEL_NOTE.md: the exact manifest change for the phone (not built).

What failed or is blocked

  • Moonshine v2 in the browser: transformers.js (4.3.2, 4.4.0-next) has no moonshine_streaming support, and the official @moonshine-ai/moonshine-wasm 0.1.6 ships only a SIMD + pthreads build, which needs COOP/COEP headers the game does not send (a single-thread build has to be compiled from source with emsdk 4.0.8 and ONNX Runtime). Not worth it: v2 small is +3.7 points on US/UK and -0.6 on the Indian proxy against Moonshine base, at 142 MB.
  • WebGPU: this server has no GPU, so headless Chromium has no adapter; every browser number is WASM (one thread, as players without cross-origin isolation get). On a player's GPU Moonshine base would be faster; Whistle has no WebGPU path.
  • Whistle's native x86 engine has a cliff above 5 s of audio (0.2 s → 1.5 s per clip with 2 threads, worse under load); the WASM build scales smoothly (0.73 s under 4 s, 1.9 s over 6 s).
  • Phonon-2.5 English as a 'tiny' phone model: the 157.6 MB file is an MLX (Apple silicon) container; the Android LiteRT CPU build is 0.94 GB and its card reports 6.1 GB peak RAM on a Galaxy S26 CPU run.
  • No real recordings yet: ml/data/gold/live/ is empty, so every number is synthetic speech (Kokoro). The Indian-accent set is Kokoro's Hindi voices reading English, a proxy, not the owner.

Notes

  • Contextual biasing paid off for Whistle only with the command words: names alone 61.6% / 61.9% (one decode), names + ATC words 64.4% / 66.9%; WER 36.7 → 32.7% (US/UK).
  • Where Whistle loses (US/UK, against Moonshine base): late start 56% vs 64% and clean 72.5% vs 77.5%; it ties on laptop (75%) and radio (54% vs 52.5%). On the Indian-accent proxy it is 8 points behind (66.9% vs 75.0%), the gap that matters most for the owner.
  • Sent wrong (a wrong command the game would send) is 2-7% for every engine: the verifier holds back most misrecognitions, so the differences are in how often the player has to repeat.

How it was measured

  • Clips: ml/stt/bench2/clips (160 situations x clean/laptop/radio/late, US/UK Kokoro voices), even ids: 320; ml/stt/bench2/clips_in (Kokoro Hindi voices, clean/laptop), even ids: 160.
  • Score: ml/stt/bench2/score.ts with S1_MODEL=2m-grpo-v1; 'exact' = the game's n-best + repair + S1 chain ends on the gold command; baselines were rescored with today's scorer (the verifier lowered every engine's sent-wrong since round 2).
  • Browser: ml/stt/bench2/edge_browser.cjs, headless Chromium (playwright), the game's worker, 40 clips (mean 5.0 s), WASM; RAM = PSS of all Chromium processes above a blank page (peak); download = bytes fetched. The machine was shared (load average 12-20), so latencies are pessimistic.
  • Phone: mobile/tool/stt_bench.dart (the app's SttEngine and hotword builder, sherpa-onnx on Linux x86, 2 threads).
