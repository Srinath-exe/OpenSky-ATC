Slots per kind grow with the square root of how common the kind is in the data: common kinds get more, rare ones still get one. The sentences are the engine's own phrasing (FAA wording at US airports, ICAO elsewhere), so the right command is known exactly. Phrases the rules read as a different command are left out (the engine says “give way to the Qantas, then continue” for a single give-way, and names a turn direction the AI left open in cancel-approach), so those two kinds are not in the set. Recording order interleaves the groups (each block of 10 = 6 validation, 3 Sydney, 1 own words). Validation airports: EGLL 7, KBOS 6, KJFK 6, KLAX 6, KSFO 6, LFPG 6, OMDB 6, RJTT 7, VHHH 6, VIDP 7, WSSS 7.

Dry run · synthetic speech

The pipeline, proven on 30 Kokoro clips

Kokoro-82M clips from the GPU bake-off (six voices), posted through the real API handler into a temp gold directory and scored exactly like a recording. These are not your voice: they check that storage, recognisers, rules, model and report all work, and give the synthetic baseline to compare with.

Waiting for recordings · 0 of 100

This section fills in when the clips are scored. The same charts as the dry run above, split into validation airports, Sydney and own words, and the clips each recogniser got wrong.

  1. Open /voice/record.html#k=… (the key is in ml/data/gold/.key on the server) in Chrome or Edge, so the browser recogniser runs too.
  2. Read the 100 prompts; about 15 minutes. Any prefix of the set is already a fair mix.
  3. On the server: ml/.venv/bin/python ml/stt/score_gold.py score (CPU, about 10 minutes for 100 clips). It rebuilds this page.
Commands

Record, score, rebuild

ml/.venv/bin/python ml/stt/score_gold.py prompts     # rebuild the prompt set (seeded; already done)
ml/.venv/bin/python ml/stt/score_gold.py score       # every clip in ml/data/gold -> scores + this page
ml/.venv/bin/python ml/stt/score_gold.py dryrun      # the same pipeline on Kokoro clips
python3 ml/report/build_gold.py                      # this page only
