The idea

Two ways to write a command line

Autoregressive (AR)
Predict the next token from everything before it, append it, repeat. A causal mask stops each position seeing the future. One forward pass per output token; the KV cache makes each pass cheap.
Masked diffusion LM
Start from a canvas of L [MASK] tokens and fill it in over S passes. Attention is bidirectional: every slot sees the prompt and every other slot, decided or not.
Forward (masking) process
The corruption used in training: pick a noise level t between 0 and 1 and replace each answer token by [MASK] with probability t. t = 1 is pure noise (all masks).
Denoising
The learned reverse step: given a partly masked canvas (and the prompt), predict the clean token at every masked slot at once.
Low-confidence remasking
At each decoding pass keep only the most confident predictions; the others go back to [MASK] and are predicted again next pass, now conditioned on what was kept (LLaDA).
Steps S
Passes over the canvas. S = 1 is fully parallel (every slot from one pass), S = L keeps one token per pass. Fewer steps = faster but each slot is guessed without seeing its neighbours.

Training · 1200 steps × batch 32, 1 CPU thread each, same data

Same compute, how far did each get?

Diffusion objective (MDLM / LLaDA): mask the answer at a random level t, score cross-entropy only on the masked slots, and weight by 1/t. That weighting comes from the ELBO (evidence lower bound): averaged over t it is an upper bound on the answer's negative log-likelihood, so minimising it pushes the likelihood up, as the AR loss does. Light masking (small t) gives few, easy targets, so each counts more.

A trie needs left-to-right; diffusion needs another trick

The AR model walks a trie of the callsigns in the game state, so it can never name an aircraft that is not there. A diffusion model fills slots in any order, so we tried three alternatives.

Span (exact search over the callsigns in the state) is worth +9 points over plain argmax, and it is why callsign accuracy reaches 97–99%. Masking invalid first tokens helps only slightly; snapping to the nearest callsign afterwards is in between. Any model that can score a sequence can use span scoring, AR included.

Borrowed back · shipped AR model · n = 1000 each

The span trick works in the AR model too

Span scoring is not specific to diffusion: any model that can score a sequence can rank whole callsigns. In the shipped AR model, score each callsign in the state by its log-likelihood after the prompt (plus a word boundary), keep the best, then decode the rest greedily as before.

The prefix-cache question. In an AR model a token's keys and values never change once computed, because it cannot see later tokens: cache the prompt once and every later pass is one token. In a bidirectional model the prompt also attends to the canvas, so its keys and values change whenever the canvas changes. Caching them is an approximation, not an identity. We measured two: reuse the prompt's keys/values from pass 1 (Fast-dLLM's prefix cache) and encode the game state alone while the player is still talking.

Verdict

Autoregressive wins this task; diffusion is only competitive when it starts from the AR model

From scratch, same budget, diffusion lost badly. After 1200 steps × 32 on one CPU thread each, the AR model reached 72.2% val / 66.0% Sydney. The masked diffusion model reached about 1%: it writes well-formed lines (AAL673 Fly heading 25) but barely uses the transcript. Its likelihood bound is 17.8 nats per command against the AR model's 2.2. Even with 90% of the answer visible (t = 0.1) it scores 1.95 nats per missing command token, while the AR-initialised model scores 0.07.

It is not a bug, and not the 1/t weight. The same code memorises 64 commands (loss 0.009), learns fine from an AR start, and a second from-scratch run with a plain mean cross-entropy loss (no 1/t weight, so much less gradient noise) reached only 2.1% (callsign 19%) after the same 1200 steps. The AR loss gives about 10 supervised predictions per command, each with the full left context. The masked loss gives fewer, and at high t it asks for tokens with no answer context at all, so learning to copy from the transcript is far slower. Masked diffusion is known to need many times AR's compute to reach the same likelihood; at 0.19 epochs on a CPU it never got there.

Adapted from the shipped AR checkpoint (as Dream-7B was from Qwen), diffusion becomes competitive. 8.5% at step 0, 70% after 300 steps, 88.5% after 1200 (n = 200 curve). On the full sets: 88.9% val / 86.9% Sydney at S = 8, and 91.5% / 89.4% at S = L. That is 2.7 points under its parent on val and 2.6 points over it on Sydney, mostly from callsigns (99.1% vs 91.9%).

The callsign gain is a decoding trick, not diffusion, and it is the most useful result here. The span constraint scores every callsign in the state and keeps the best; plain argmax loses 9 points. Applied to the shipped AR model (score each callsign by likelihood instead of walking the trie greedily), it lifts val from 94.2% to 98.2% and Sydney from 86.8% to 93.9%. Callsign accuracy goes to 99.7% / 99.4%. Latency rises from 51 to 72 ms on 1 thread.

Latency: a pass is cheap, but this answer is short. One diffusion pass costs 27 ms over prompt + canvas (388 tokens) and 4 ms over the canvas alone with the prompt cached. The AR model needs about 9.5 passes, 48 ms (24 ms if the game state is prefilled while the player talks). S = 1 diffusion is the fastest decoder here, 8 ms after release with the state cached, but only 70% right. At AR-level accuracy (S ≥ 8) diffusion takes 45–66 ms against AR's 24 ms.

Bidirectional prompt caching worked in practice. In theory the prompt's keys/values change with every canvas update. Reusing them from pass 1, or encoding the game state alone while the player talks, cost no measurable accuracy (89.6% / 89.6% vs 89.4% exact on the same 500 val rows) and cut S = 8 from 208 ms to 66 / 45 ms.

When diffusion would win

  • Long outputs. A canvas pass costs about 4 ms with the prompt cached, while an AR token step costs about 2.2 ms. Diffusion wins once it keeps more than about 2 tokens per pass. The τ = 0.9 schedule keeps about 5, but a 10-token command has only about 2 passes' worth to save. A 200-token plan would save far more.
  • GPU at batch 1. Decoding is memory-bound there, so a pass over 25 slots costs about the same as a pass over 1 token. S passes against N sequential AR passes is then a direct speed-up whenever S is much smaller than N. That is the Mercury / Gemini Diffusion pitch, and it shows mostly on long outputs. On a 1-thread CPU the work is compute-bound, so the 25-slot pass costs more.
  • Editing and infilling. "Make that seven thousand": remask only the altitude slots of the line already in the command bar and denoise them with both sides visible. An AR model cannot condition on the text to the right.
  • An AR model already exists. Adaptation took 1200 CPU steps, and it gives a parallel decoder with a per-slot confidence and a speed/quality knob (S or τ) for free.

Next steps

  • Ship likelihood-scored callsigns in the browser engine. Parallel work on the same idea is in progress in ml/s1 (callsign_scoring.py, callsign_search in decode.py, s1.ts), and ml/diffusion/ar_span.py is an independent check of it. Measured here: +4.0 points val, +7.1 points Sydney, +21 ms at 1 thread.
  • Prompt-causal attention: the prompt cannot see the canvas, so prompt caching becomes exact, and K noisy canvases per prompt cost almost nothing to train. That lowers the variance that hurts small-batch masked training.
  • From scratch on a GPU at 10–20× this compute (e.g. 24k steps × 64 ≈ 45 min on an L4 ≈ $0.75), to measure where, or whether, from-scratch diffusion catches up on this task.
  • AR→diffusion with a lower learning rate (the 2e-3 peak first dropped the shipped model from 94% to about 70%) and for longer; an S = 1 or τ decoder distilled from it.
  • An edit mode in the game: remask the field the player corrects.
